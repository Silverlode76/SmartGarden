## Schaltungskonzept (aus Fritzing-Steckplatine)

```
[2× Solarpanel, je ~3–3,5V OC]   In Reihe: ~6V / "7V" OC (Fritzing-Label)
             |
    [Mini-360 Buck Converter]      Eingang: ~6V Solar
         "6V" Label                Ausgang: einstellbar ~5V → für TP4056
             |
       [TP4056 Laderegler]         Benötigt ~4,5–5V Eingang; lädt LiPo
             |
     [LiPo 110mAh 3,7V]           Akku-Typ: 6SP 061225
             |                     (direkter GND-Anschluss an Lochrasterplatine)
             └─────────────────────────────────────────┐
                                                        |
[Lochrasterplatine]                                     |
   [STM32F103C8T6 Blue Pill] ←────────── 3,3V (vom 3V3-Pin des Blue Pill)
          │
          ├──I²C (SDA/SCL + 2× 10kΩ Pull-up)────[GY-BME280 (lila)]
          │
          └──SPI (MOSI/MISO/SCK/NSS + DIO0/DIO1)──[SX1278 LoRa Modul (blau rechts)]
                                                         → 433 MHz proprietär

Debug-Ausgang: USART3 → PB10 (TX) / PB11 (RX)
```

> **Hinweis zu Spannungsannotationen:** In der Fritzing-Steckplatine sind die Labels  
> „6V" und „7V" vom Designer manuell gesetzt. „7V" = Solar-Leerlaufspannung (OC),  
> „6V" = Betriebsspannung an Mini-360-Eingang. Die Fritzing-Bauteilbibliothek listet  
> die Solar-Zellen mit „1,5V/1mA" (Standardwert des Fritzing-Bauteils) — das spiegelt  
> **nicht** die reale Betriebsspannung wider. Tatsächlich verwendete Panels: ~3V/Stück  
> in Reihe = ~6V, aber mit sehr geringem Strom → TP4056 arbeitete grenzwertig.

## Erkenntnisse aus diesem Prototyp

### ✅ Was funktionierte

- STM32F103C8T6 grundsätzlich lauffähig
- BME280 liefert gute Messwerte (Temp, Feuchte, Luftdruck)
- LoRa-Kommunikation (proprietäres Protokoll) funktionsfähig
- Konzept der solarbetriebenen Node validiert

### ⚠️ Kritische Probleme

| Problem | Ursache | Lösung in v0.1 |
|---------|---------|----------------|
| **SX1278 = 433 MHz** (nicht EU868) | SX1278 Frequenzbereich 137–525 MHz → kein LoRaWAN EU868 möglich | TTGO LoRa32 mit SX1276 (137–1020 MHz), EU868-fähig |
| **Solarzellen viel zu schwach** | 2× 1,5V / 1mA in Reihe = 3,0V / 1mA = **0,003W** — für Laderegler wertlos | 6W 6V Solarpanel (~1A) |
| **TP4056 lädt nicht bei Schwachlicht** | TP4056 benötigt Vmin ~4,5V — 3V Solarspannung reicht nicht | CN3791 MPPT startet ab ~4V, effizienter bei diffusem Licht |
| **Kein MPPT** | Mini-360 ist einfacher Buck-Converter, kein Maximum-Power-Point-Tracking | CN3791 MPPT-IC |
| **110mAh viel zu klein** | 110mAh bei ~5mA Standby = ~22h Autonomie ohne Solar | 2× 18650 (~5000mAh) → ~1000h Autonomie |
| **Kein LoRaWAN** | Eigenes proprietäres Protokoll, kein TTN möglich | LoRaWAN + MCCI LMIC Library |
| **STM32 Toolchain komplex** | STM32CubeIDE, HAL, manuelle SPI-Konfiguration für SX1278 | ESP32 + Arduino Framework → schnellere Iteration |

### ❌ Warum abgelöst

Der Prototyp hat bewiesen, dass das **Konzept** funktioniert.  
Die **Plattform** (STM32 + SX1278 + TP4056 + 110mAh) ist für ein Outdoor-Solar-Produkt ungeeignet.  
→ Vollständiger Plattformwechsel auf ESP32 + SX1276 (TTGO LoRa32) für v0.1.
